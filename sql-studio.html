    Follow a question.
    Find the connection.
    A browser SQL workspace for querying local tables with DuckDB. Inspect a file, compare groups, or combine tables using explicit queries.
    How to query a dataset
    1. Mount your files. Wait for the engine to become ready, then mount CSV, JSON or Parquet files. Each file becomes a temporary table.
    2. Inspect the schema. Check table names, column names and detected types. Quote identifiers with double quotes when needed.
    3. Ask your question. Start with SELECT, add WHERE or GROUP BY, or insert a schema-based example from the SQL guide. Inserting does not execute it. Run the query when ready; DuckDB syntax can differ from other databases.
    4. Keep your result. Browse results in pages of 100 rows and export the complete successful result as CSV. Save a named query or revisit successful history. Tables must be remounted after refresh.
    A workspace for exploration
    Queries run against temporary browser tables. Keep your original files and download useful results. Browser memory and network availability for engine assets affect what you can run.

    Which SQL does SQL Studio use?
    SQL Studio uses DuckDB SQL. Common SELECT queries, joins, grouping and window functions are available, but database dialects differ. MySQL or SQL Server syntax may need adjustment. The SQL guide provides examples using your mounted tables; inserting an example never runs it automatically.
    Which files can I query?
    Mount CSV, JSON or Parquet files as temporary tables and join them in a query. Inspect detected names and types in the schema. Double quotes identify tables or columns, including names with spaces; single quotes represent text values.
    How do I add a derived column or parse dates?
    Use a SELECT expression to add a result column without changing the imported table. The guide includes YEAR(TRY_CAST(column AS DATE)) for date or ISO text values, and TRY_STRPTIME for explicit text date formats. Failed try-conversions become NULL. Adding generated columns after table creation is not supported by this engine.
    What is saved, and does my data leave the browser?
    Files are processed by browser DuckDB; the bundled engine loads from this site. SQL that accesses remote URLs or installs extensions can make additional network requests. Query text, up to 30 recent successful queries and 50 named queries can be stored in this browser. SQL can contain sensitive literal values. Storage may be unavailable, cleared or full; tables and query results are not persisted. Remount files after refresh and download useful results.
    Does exporting include every page, and what are the limits?
    Results display 100 rows per page; CSV export includes the complete most recent successful query result, regardless of the page shown. Empty results have no CSV export. Results stay in Arrow format in browser memory; only the visible page is converted for display. CSV export converts rows in chunks, but the download still needs memory. Pagination does not limit engine memory use. This is a temporary analytical workspace, not a persistent database server.
